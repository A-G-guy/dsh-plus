# 插件存储规范

本规范约束 dsh-plus 系列插件在 `$DSH_HOME` 下的数据落点。核心原则：

1. **分类落位**：缓存/日志/复杂文件 → `$DSH_HOME/dsh-plus/<pluginId>/`；纯用户配置 → 官方 settings 接口；密钥 → 官方 credentials 接口。批量与派生数据（导入结果、目录快照等）一律归缓存类落插件数据目录，**不得进 settings**（settings 整值序列化进 profile 的 `cordis.patch.yml`，大数组会淹没配置文件）。
2. **不做代码兼容**：新版代码只读写新位置，无 fallback、无自动迁移。
3. **旧数据保留**：迁移由 `dshctl migrate-storage` 复制式完成，旧文件原样保留，删除走人工清单确认。

## 数据分类与落位

| 分类 | 落位 | 写入通道 | 例 |
|---|---|---|---|
| 缓存/日志/运行期状态 | `$DSH_HOME/dsh-plus/<pluginId>/…` | `@dsh-plus/shared` 的 `pluginDataPath` 等 helper | 用量缓存、审计日志、journal |
| 纯用户配置 | profile 行级覆盖层（profile 目录 `cordis.patch.yml`；`settings.update` 即写该文件，`$DSH_HOME/settings.yaml` 已废弃） | `dsh-settings` 官方接口（`describe/update/mutate`；volatile 字段原位提交） | 行为开关、阈值、周期（**仅小配置**：整值序列化，批量数据会淹没配置文件） |
| 密钥/凭据 | `$DSH_HOME/.credentials.yaml` | `dsh-credentials` 官方接口（`credentialRef` + `set`/`resolve`） | API key、SMTP 密码 |

## 插件数据目录（`dsh-plus/<pluginId>/`）

由 `packages/shared/src/plugin-data.ts` 统一提供（唯一合法入口，禁止散拼路径）：

- `pluginDataPath(pluginId, ...segments)` — 解析绝对路径；pluginId 与路径段均做边界校验。
- `pluginDataDir(pluginId)` / `ensurePluginDataDir(pluginId)` — 目录解析与递归创建。
- `writePluginDataFile(pluginId, fileName, data)` — 委托官方 `@deepseek-ai/dsh-atomic-write`
  的 `writeFileAtomic` 原子落盘：内容仅接受字符串、替换 inode 显式 `0o600`、
  Windows 对 EACCES/EBUSY/EPERM 瞬态 rename 有界重试、父目录自动创建。
- 字节型数据（图片等）走 `commitTmpFile(tmp, target)`（`atomic-write.ts`）：
  流式写完同目录 tmp 后 rename 提交，rename 失败回退复制保证数据落地。
- 各包文本写入（usage-panel 缓存/价目、web-files 用户文件与偏好、image-studio
  索引重写）统一经 `@dsh-plus/shared` 的 `atomicWriteFile`（`USER_FILE_MODE=0o666`
  仅用户内容文件，插件数据默认 `PLUGIN_DATA_FILE_MODE=0o600`）。

例外：lifeboat 受"零 dsh-plus 内部依赖"铁律约束，自带等价实现（`state-file.ts`），落点规范一致。

## settings 命名空间约定

- 每插件至多一个 settings 命名空间（`dsh-plus-<pluginId>`），只承载**纯配置**（可公开、可手编、无派生状态）。
- 运行期产生的状态（journal、缓存、计时器游标等）一律不得写入 settings 命名空间。
- 批量与派生数据（导入结果、目录快照等）同样不得写入：`settings.update` 整值序列化进
  profile 的 `cordis.patch.yml`，大数组会淹没配置文件（事故案例见
  [事故记录](事故记录.md)）。
- `role('secret')` 字段只允许出现在行级 Config（cordis 组合层注入场景）；用户层配置走 credentials。

## credentials 引用约定

- 引用名（`credentialRef` 的 POSIX 环境变量名）以 `NOTIFY_EMAIL_` / `<PLUGIN_ID>_` 前缀开头，全大写。
- 插件经 `ctx.inject(['credentials'])` 或可选探测获取 seam；解析**每次操作即时 resolve**，不跨操作缓存。
- 配置 UI 一律用 `describe` 探测"已配置与否"，不回传值。

现有引用：

| 引用名 | 属主 | 用途 |
|---|---|---|
| `NOTIFY_EMAIL_SMTP_PASS` | notify-email | SMTP 密码/授权码（mailer 发送时 resolve） |
| `IMAGE_STUDIO_PRESET_<ID>` | image-studio | 提供商预设的 API key（`<ID>` 为预设 id 大写下划线化，每次生图任务即时 resolve） |

## 迁移与删除流程

1. `dshctl migrate-storage`：复制式迁移 + 密钥入 credentials + 清单落盘（幂等可重入，先备份）。
2. 用户重启切换新版插件并验证。
3. 用户确认后，按 `dsh-plus/migrate-manifest.json` 清单精确删除旧数据（删除前再次列清单人工确认）。

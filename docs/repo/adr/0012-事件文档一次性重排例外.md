# ADR 0012：一次性重排 event 文档，append_only 临时降级

- 状态：已采纳（2026-10-07）
- 背景：ADR 与事件文档长期互相重复——每篇 ADR 自带「事故因果链」，事件叙述又问世于
  [事故记录](../事故记录.md)；部分 ADR 尾部累积了多条后续决定（「更新」小节），一篇
  ADR 承载多个决策事件。仓库规范要求「`fact` 与 `event` 不重复内容」，而
  `docs.append_only = "error"` 只允许追加，无法就地拆分。

## 决策

1. **事件文档一次性重排**（本次，且仅本次）：
   - 事故因果链从 ADR 移入[事故记录](../事故记录.md)，ADR 只留背景简述 + 决定 + 后果
     并回链事件条目；
   - 机制类事实（如 profile 模块回退层）移入[官方机制参照](../reference/官方机制参照.md)；
   - 配置类事实（如类型检查配置要点）移入[仓库管理规范](../仓库管理规范.md)；
   - 一篇 ADR 拆成一决策一 ADR：新增 0009（pre-commit 类型检查退役）、0010（devDeps
     跟随运行期平台线）、0011（Actual CLI 不进依赖）；0005 失效的第 5 条删除并指向
     0006；0007/0008 的多决策段落各自独立成篇。
2. **`docs.append_only` 在重排期间临时降为 `warn`**，重排与引用修正完成后**在同一推送内
   恢复 `error`**；本 ADR 即该例外的登记。
3. **此后不再重排**：event 文档回到只增不改；结论修正一律新开一篇并引用旧篇
   （[adr/0006](0006-提交门禁执行文档规则.md) 既定口径）。ADR 粒度纪律：一篇 ADR 只记
   一个决策事件，后续决定另开新篇并互相引用。

## 后果

- 事故叙述与决策记录各有唯一归属，交叉引用取代重复内容；
- ADR 目录编号连续（0001–0012），INDEX 由 `projects-go index` 重建；
- 本次重排使 event 文档出现删除行，`git log` 是唯一的改写审计面；若日后再次需要结构性
  重排，必须同样先降级、后恢复并在新 ADR 登记，不得长期放宽。

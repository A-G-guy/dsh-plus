# ADR 0002：类型检查成为守门步骤（逐包 tsc --noEmit）

- 状态：已采纳（2026-09-10）
- 背景事件：生产 GUI 输入 `/` 只剩 Skills 分组，官方全部斜杠命令
  （compact/export/feedback/goal/permission/plan 等）从菜单消失；
  宿主 RPC `commands/list` 却正常返回 7 条。

## 事故因果链

1. dsh 平台升到 `0.1.5-rc.1` 后，官方把客户端契约
   `CommandContribution.description` 由 `string` 改成惰性求值 `() => string`。
2. 插件 `@dsh-plus/secret-env` 的 `/var` 命令仍传字符串。它没有引用官方契约类型，
   而是**手抄了一份本地结构类型**——抄的是 alpha 线形状，于是升级平台版本线时
   没有任何机制提示这份副本已过期。
3. `dsh-client-ui-commands` 的候选合成期调用 `contribution.description()` →
   `TypeError: contribution.description is not a function`。
4. `dsh-client-ui-input-trigger` 对源失败的设计是**静默摘除该分组**（只写浏览器
   console）→ 整个 `command` 分组消失，只剩 `skill` 分组。

关键点：**从构建到单测，整条流水线没有一步会因此变红**。
`dshctl test` 当时 = biome（风格）+ tsdown（只转译，不做类型校验）+ node --test（运行时）。
契约形状漂移（字符串→函数、必填→可选、字段改名）恰好落在三者共同的盲区里，
只能在真实浏览器里以运行时异常暴露。

## 决定

1. **新增 `dshctl typecheck [包...]`**：逐包执行
   `tsc --noEmit -p packages/<包>/tsconfig.json`，并行调度、失败打印原文错误行并汇总。
2. **纳入守门链路**：`dshctl test` / `dshctl finish` 在 biome 之后、构建之前执行全量检查。
   置于构建之前是因为类型检查比构建快一个量级，早失败早反馈。
3. **逐包配置而非单一根配置**：host 半与 client 半的类型环境不同（node vs DOM）。
   分包 `tsconfig.json` 才能让「host 代码误用 `document`」这类越界在类型层被拦住，
   也才能让 host-only 包保持 `lib: ["ES2022"]` 的紧约束。
4. **每个包都必须有 `tsconfig.json`**：闸门以「含 `tsconfig.json` 的包」为检查目标，
   漏配即静默逃逸。由 `scripts/tests/test_typecheck.py` 断言"全部包都在闸门内"，
   由 `dshctl new-plugin` 脚手架自动生成（UI 模板给 jsx+DOM，host 模板只给 node）。
5. **消费官方契约必须引用官方类型**：本地结构类型副本一旦与官方漂移，类型检查也救不了
   （副本自己就是"正确"的）。`packages/secret-env/src/client/command.ts` 已改为直接引用
   `CommandContribution`，并把对应 `@deepseek-ai/*` 包补进 `devDependencies` 保证同源。
6. **修类型错误的手段受限**：禁用 `any` / `as any` / `@ts-ignore` / `@ts-expect-error` /
   `@ts-nocheck` 消错，也禁用非空断言 `!` 敷衍 possibly-undefined。唯一例外是运行期形状
   确有保证时的 `as unknown as X`，且必须就近注释说明为什么安全。
   没有这条，闸门会退化成"用 any 把红灯刷绿"，比没有闸门更危险。

## 配置要点（踩过的坑）

- `allowImportingTsExtensions: true` 必须开：本仓源码一律带 `.ts`/`.tsx` 扩展名导入
  （bundler 解析 + tsdown 打苞约定），否则每个内部导入都报 TS5097。
- 该选项要求 `noEmit`/`emitDeclarationOnly`：与 `noEmit: true` 同置。
  已实测 `noEmit` 不影响 tsdown 的声明产物（改动前后 `lib/**/*.d.ts` 逐字节一致）。
- **`@types/node` 必须显式列入 `types`**：把包放到根 `node_modules/@types` 也不够，
  自动 `@types` 收录对 `node:` 前缀模块（`node:http`、`Buffer`、`process`）不生效，
  会报 TS2591。写入 `tsconfig.base.json` 的 `types: ["node"]` 一次解决全部包。
  该设置不影响 JSX：react 类型经显式 `import ... from 'react'` 解析，不依赖全局收录。
- 环境声明 `.d.ts`（如 lucide 深路径通配声明）**必须随使用它的源文件进 program**：
  消费方经源码级打苞导入该文件时，兄弟 `.d.ts` 不会自动成为 program 根。
  用 `/// <reference path="./x.d.ts" />` 把它钉在源文件上。

## 推论

- 官方客户端契约漂移从此在本地 `dshctl test` 阶段即可捕获，不再依赖生产浏览器实测。
- 类型检查同时暴露了历史遗留的真实缺陷（如 ui-mobile-fit 调用了从未定义的
  `isTextField`），这类问题过去只在特定交互路径下以 ReferenceError 出现。
- 契约密集面（斜杠菜单、设置页、插槽）仍建议在真实 GUI 过一遍：类型只保证形状，
  不保证语义（例如官方把"描述"改成"描述函数"时，返回什么文案仍可能不合预期）。

## 更新（2026-10-02）

- **pre-commit「暂存包逐包 tsc」退役**：门禁统一为 projects-go 后，其 pre-commit 只跑
  固定检查集、不支持外挂脚本链，为统一门禁放弃该步（原应急旁路 `DSHCTL_SKIP_TYPECHECK=1`
  一并移除）。裸 `git commit` 不再即时跑类型检查——本决定 1–3 的守门链路
  （`dshctl test` / `finish` / `release publish`）与根脚本 `pnpm test` / `pnpm typecheck`
  不变，仍是强制点；提交前必须自行跑 `pnpm test`。

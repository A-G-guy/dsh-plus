# ADR 0010：定制语义现场读本机资产，不内置模型快照

- 状态：已采纳（2026-10-06）
- 背景：ADR 0009 交付报表与仪表盘能力后，实际派活暴露出信息缺口——组件类型的
  `meta` 字段、实验开关是否开启、报表字段的合法取值，都只在官方客户端/服务端实现里。
  预算里没有同类组件可抄时（新类型、实验类型），执行者只能去网上翻官方仓库源码，
  既慢又可能与本机版本不一致；猜字段名的后果更糟：写入成功、界面什么都不渲染。
  需要定一件事：**这些语义从哪里来**。

## 决策一：运行期读本机资产，不内置快照

三类事实各有本机来源，全部现场读取、随环境版本走：

| 事实 | 来源 |
| --- | --- |
| 组件类型、meta 字段与类型、共享类型 | 官方 CLI 自带的 `@actual-app/core` 模型源码（`src/types/models/dashboard.ts`） |
| 实验开关清单 | 同包 `src/types/prefs.ts` 的 `FeatureFlag` 联合 |
| 开关当前取值、周首/货币等偏好 | 当前预算的 `preferences` 表 |
| 界面侧语义（区间词汇、卡片渲染、公式可用函数） | 服务端静态托管的 Web 客户端源码（chunk 的 source map 里带原始源码） |

**不内置这些内容的快照**：快照会随上游版本静默过时，而错误后果恰恰是静默的
（字段名照写、界面不渲染）。因此解析失败、源码缺失、source map 不可用一律显式报错，
并给出替代路径（`--core-dir`、`--kind core`、或在界面建一个样板组件后照抄）。

## 决策二：客户端源码经「本机服务端」取，不经外网

Actual 服务端静态托管整个 Web 客户端，入口 bundle 里带按需加载的 chunk 清单，
每个 chunk 都有内容哈希命名的 `.map`。因此参考族按
「首页 → 入口 bundle → chunk 列表 → 各自的 `.map`」现场发现并读取，
缓存到 `<dataDir>/client-source/<服务端>/`（资产名内嵌内容哈希，可长期缓存；
首页 HTML 每次重读以便发现新版本）。这样读到的就是**用户界面正在跑的那份代码**，
而不是某个外网 commit；也避免了在插件里打包上游源码带来的许可与体积问题。

## 决策三：参考族是只读、可免预算的独立族

新增 `reference` 族（`widgets` / `prefs` / `source` / `report-options`），动作表里
除 `prefs`（要读预算偏好表）外都标 `needsBudget: false`：不加载官方 api、不取锁、
不下载预算，拿到服务端地址与缓存目录即可执行。理由：查字段名是写组件的前置动作，
不该付一次同步的代价；也避免「预算临时取不到 → 连字段清单都查不了」。
本地动作拿到的预算访问面是守卫对象，被访问即报接线错误。

## 影响

- `@dsh-plus/actual-reports` 新增 `src/core-model.ts`（模型/开关解析）、
  `src/core-source.ts`（本机源码树）、`src/client-source.ts`（客户端资产发现与缓存）、
  `src/prefs.ts`、`src/reference-commands.ts`；动作表按族拆成三个文件以免单文件超限。
- `ReportsIo` 增加 HTTP 窄面（只访问 `serverUrl` 指向的服务端）与 `isDirectory`；
  新增 `--core-dir` / `DSH_ACTUAL_CORE_DIR` 覆盖项，供自定义部署与测试使用。
- `@dsh-plus/actual-mcp` 的只读动作清单加入 `prefs` / `source` / `report-options`；
  `actual` 预设提示词明确「定制细节用 reference 工具查，不要联网搜官方源码」，
  并写清实验开关未开启时的后果。

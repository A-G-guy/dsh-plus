# ADR 0006：提交门禁按索引执行文档规则，append_only 恢复 error 级

- 状态：已采纳（2026-10-03）
- 背景：ADR 0005 第 5 条把 `docs.append_only` 降为 warn，理由是 `projects-go doc`
  每次把 `last_modified` 重写成上一提交时间，这一行在 event 文档里同样表现为「删除
  一行」，error 级会让元数据自动维护与 append-only 互斥。根因不在 append-only 本身，
  而在两处实现：判定没有豁免工具自己维护的字段；pre-commit 在 `hook.fix` 默认 true
  下只做 front matter 维护，不跑文档规则（`required_fields` / `scope` / `language` /
  `append_only`），「error 级」实际只由 `projects-go check` 承载。

## 决定

1. `projects-go` 侧修正（`feat(gate)!`，2026-10-03）：
   - pre-commit 与 `check --staged` 判同一份索引内容，并执行同一套文档规则；
     `hook.fix = true` 时先修复并重新暂存 front matter 与 INDEX.md，再判定。
   - append-only 判定改按 hunk 过滤：只动 `last_modified`（含别名）的 hunk 不计为
     改写，工具自身的维护不再触发该检查。
   - `doc` / `docsize` / `agents` 的 `--staged` 一律判索引：未 `git add` 的草稿不再
     拦下无关提交。
   - `last_modified` 单一口径：内容有未提交改动时写运行时间（钩子即提交时），
     已覆盖该次改动的时间戳不再重复刷新（未提交期间不随每次运行漂移），内容未变
     保留原值，字段缺失才用该文件上次提交时间补齐。
   - 存量（baseline 之前）的检查项默认只汇总一行计数，`--all` 才逐条列出。
2. 本仓 `projects.go.toml`：`[docs.append_only] level = "error"` 恢复；启用
   `docs.language = "zh"`（计数只看正文，术语 token 不计入，实测 41 篇最低占比 0.59）；
   `docs.scope.exempt` 只写本仓新增的一条（列表键默认叠加，不再复述内置豁免）。
3. ADR 0005 第 5 条自本 ADR 起失效；0005 其余决定（biome 承载架构门禁、不引入
   dependency-cruiser、例外只在 `biome.json` 登记）继续有效。

## 后果与边界

- 缺 `type`、改写 event 文档正文现在会拦下提交；确需修正 event 文档结论时新开一篇
  并引用旧篇（本 ADR 即为对 0005 的修正）。
- 未 `git add` 的文档改动不参与提交判定，也不会被钩子修复；工作区副本与索引不一致
  时，钩子保留工作区改动并提示 `unstaged changes to this document`。
- 提交判定以 `projects-go check --staged` 为准；该命令与钩子结论一致，是全仓
  `projects-go check` 之外更贴近提交的视角。

# 官方版本变更记录

记录官方 dsh（`@deepseek-ai/*`）各版本相对上一版本的破坏性与行为变更，以及本仓的适配动作。
当前生效的机制结论见 [官方机制参照](官方机制参照.md)；由这些变更引发的事故见
[事故记录](../repo/事故记录.md)；客户端 UI 结构（选择器锚点）的逐版本跟进见
[ui-mobile-fit 上游跟进记录](../../packages/ui-mobile-fit/docs/上游跟进记录.md)。

新版本在文件最前追加；已有条目只增不改，结论修正时新开条目并引用旧条目。

## 0.2.1-alpha.1（2026-10-04 起为本仓当前基线）

- 全仓 platform-sync 到 `0.2.1-alpha.1`，插件 peer 声明统一改 `^0.2.1-alpha.1`（全部平台包；
  基座 cordis `^4.0.5-alpha.1` / schemastery `^3.18.5-alpha.1`）。兼容下限仍为 0.2.0，
  不支持 0.1.x。历史基线见文末「兼容基线历史」。
- devDeps 停在 `0.2.0-rc.1` 会导致逐包 `tsc` 报
  `Property 'webServer'/'credentials' does not exist on type 'Context'`——平台包的类型增强
  与代码目标线错位；全仓 platform-sync 后消除。

## 0.2.0-rc.1 相对 0.1.7 的破坏性变更（2026-09-29 实测）

- **兼容预检按 peer 判定，范围不覆盖即整体禁用**：boot 期 `prepareProfileEntries`
  读每个 profile 行 manifest 的 `peerDependencies[@deepseek-ai/dsh*]`，与运行时版本
  不符即 `dsh: disabling profile plugin …` 并置 `disabled`（bundle 行则整包
  `skippedBundles`）。`^0.1.7-rc.1` 不覆盖 `0.2.0-rc.1`（0.x caret 上界 `<0.2.0`）
  → 升级后插件全部「未加载」、无异常堆栈。仓内统一改 `^0.2.0-rc.1`
  （`dshctl platform-sync 0.2.0-rc.1`），**兼容下限即 0.2.0，不回兼容 0.1.x**。
- `DeepSeekAdapterOptions.resolveApiKey` 删除，改为
  `resolveAuth: (connection) => Promise<DeepSeekRequestAuth>`：认证头由插件一次性给出
  （`{ headers, onRequestError? }`）。官方 `llm-deepseek-api-key` 接线为
  `{ headers: { 'x-api-key': key } }`，与 0.1.7 适配器内部设置的头一致。
- `DeepSeekAdapter.listModels` 改读 `dependencies.discoverModels`（缺省返回 `[]`）：
  不传即模型目录为空；官方接线用 `catalogModelInfo(provider, model)` 映射
  `connection.models`。`providerName` 选项可取代 `providerInfo` 覆盖。
- 文件索引作用域改用 `connection.headers` 参与哈希（0.1.7 用 `apiKey`），由适配器
  内部 `RequestFiles` 组装，插件侧无感。
- `@deepseek-ai/dsh-llm-deepseek` 包根不再导出 `apply/inject/name`（新增
  `registerDeepSeekProvider` / `deepSeekConfigFields`）；`dsh-llm` 新增
  `ACCOUNT_QUOTA_EXCEEDED_CODE` / `projectToolUpdates`；`dsh-session` 新增
  `ToolCallRecovery` / `ToolHistoryProjection`；`dsh-client-ui-primitives` 删除
  `CODE_HIGHLIGHT_EXTENSIONS` / `languageForPath` / `OnboardingSurface`（本仓均未使用）。
- 本仓动作：`@dsh-plus/access-gate` 与官方 browser-auth 合并——官方 cookie 成为唯一凭据，
  本插件自有 token/cookie/登录端点通道删除（详见其插件文档）。

## 0.1.7-alpha.2 相对 0.1.6 的破坏性变更（本仓适配点）

- `dsh-settings` 删除 `installSection` 与 `get`：读用
  `settings.describe().find(r => r.ns === ns)?.value`（平面值）；插件 `Config`
  顶层字段需逐个 `.volatile()` 才会进 describe 视图（否则配置卡片无数据）。
- 事件 `settings/updated` 改名 `settings/document-updated`，载荷 `(ns, revision)`。
- `settingsScope` 服务删除，官方卡片改走 `configForms`
  （`@deepseek-ai/dsh-client-ui-settings`）。
- `SettingsProvider` 类型不再从 `@deepseek-ai/dsh-settings` 导出（默认导出即
  `SettingsForms` 类；`register` 已删，读写为 `describe/update/replace/mutate`）。
- 本仓动作：remote-settings 的修复面随 `settingsScope` 删除迁至 `configForms`
  （旧版 inject `settingsScope` 会在启动时报 `pending (waiting for service: settingsScope)`）。

## 0.1.6-alpha.2 相对 0.1.5-rc.2 的变更（本仓适配点）

- **DeepSeek 默认改走 Messages 协议**，官方根地址随之变为
  `https://api.deepseek.com/anthropic`（旧值 `https://api.deepseek.com`）。
  自定义 API 地址不受影响；手工配过旧官方根地址的需移除或改为新值。
- **官方默认模型目录换代号**：移除 `deepseek-v4-flash` 与
  `deepseek-v4-flash-vision-exp`，改为 `deepseek-flash`（承载 image 模态，
  `imageMaxBytes: 2097152`）与 `deepseek-v4-pro`（纯文本）。llm-pi 的
  deepseek 路由"同名继承官方目录"因此自动跟随，但**测试里硬编码的旧代号
  会失效**——已改为按能力形态从官方目录现场取样（`pickModel`）。
- **交互式终端进官方侧栏**（`dsh-client-ui-sidebar-terminal` +
  `dsh-api-terminal-controller`，已进入 web bundle 默认组合）：多标签、
  刷新恢复、主题跟随，终端由宿主 Session 配额（每 Session 上限）管理。
- **加号菜单收编文件入口**：composer 的独立回形针按钮（`file.attach`
  「添加附件」）被移除，改为 `+` 菜单的"添加"分组（`command` 命名空间
  `input.commands` = "添加文件或调用指令"，行 `input.file` = "文件"/"File"）。
  隐藏 file input 仍在 InputBar 内（`data-composer-seat`）由该行程序化 click，
  ui-mobile-fit 的触屏二次选择层因此改锚 `[role="option"]` 行。
- **右列更名**：`AppFrame` 的 `_detailsCol` → `_rightbarCol`，data 钩子
  `data-details-collapsed` → `data-rightbar-collapsed`（新增
  `data-rightbar-fullscreen` / `data-rightbar-instant` / `data-rightbar-col`）。
  右列语义变为"轨道"：面板自身 absolute 右贴边 + 滑入（`data-sidebar-right-open`），
  轨道只决定中列是否让位（`_detailsCol` 自 0.1.5 起即不存在，旧选择器是死规则）。
- **插件依赖改为运行时解析**，插件管理支持运行时卸载——插件加载/卸载逻辑需复核
  （本仓未依赖加载期解析假设，复核无影响）。
- 客户端 Session 支持多实例共存，相关 API 与 slot 有变化；`dsh-client-ui-slots`
  新增 Component Factory 面，Session 作用域 `SessionProvider` 新增显式 `session`
  target（缺省仍**继承外围绑定**，本仓隐式注册不受影响）。
- `dsh-llm-pi-ai` 图像请求预算类型由 `ImageRequestPolicy` 改为
  `PiImageRequestBudget`（`{maxPixels, maxBytes}`）；`maxRequestImageBytes`
  语义变为"对保留图像的硬上限，超限报 `IMAGE_OFFLOAD_REQUIRED`"。
- compat 门控表本体在 0.1.6 与 0.1.5-rc.2 **逐字节相同**（`COMPAT_GATES`/
  `COMPLETIONS_COMPAT_GATE`/`RESPONSES_COMPAT_GATE` 均一致），llm-pi 的现场推导
  与冻结快照都仍然有效。
- `dsh-host-webserver` 类型产物逐字节相同（access-gate 的 match/fallback/
  upgrades 包装面不变）；`SettingsDescribeMirror` 实现逐字节相同
  （remote-settings 的 persistence 翻转仍有效）。

## 0.1.5-rc.2 相对 0.1.2-alpha.2 的变更（本仓适配点）

- 官方 `dsh-llm-pi-ai` 的 lib 产物与 0.1.5-rc.1 逐字节相同（rc 线内部无契约漂移）；
  相对 alpha.2 的主要漂移是 compat offer 字段扩容（completions +`thinkingTokenBudgetField`/
  `vllmPriority`；responses +`supportsMaxOutputTokens`；anthropic withhold +`supportsMidConvoEffort`/
  `allowedFallbackModels`）——插件手工镜像门控表，漏收即误拒，见 llm-pi compat 文档。
- 客户端契约 `CommandContribution.description` 为惰性求值 `() => string`（rc.1 起，ADR 0002）。

## 0.1.2-alpha.2 相对 alpha.1 的破坏性变更（本仓适配点）

- `dsh-settings` 删除 `settingsNamespace()` 与 `installSettingsSection()`：
  命名空间直接以字面量传入（`register/installSection/get/update/replace/mutate`
  编译期校验小写 kebab 语法）；可选设置消费范式改为
  `ctx.inject(['settings'], sctx => sctx.settings.installSection(ctx, ns, schema, entry, hooks))`。
- `deepEqualJson`/`deepFreeze`/`JsonValue`/`assertNever` 迁至新包
  `@deepseek-ai/dsh-util-values`。
- typert 错误面：`TypertRemoteFailure` → `RemoteError`（可合并 RemoteErrorDetailsMap
  判别联合）；模型发现失败码 `model-discovery-failed` → `llm/model-discovery-rejected`。
- 会话事件信封新增可选 `ignorable: true` 标记（reader 对未知必需事件仍 fail-closed）。
- 本仓动作：官方包发布到 npm，平台依赖改走 registry，alpha.1 时代本机构建
  tarball 的 `.pnpmfile.cjs` 机制废除。

## 0.1.2-alpha 线相对 rc 系列的变更（历史）

- `dsh-client-runtime` 与 `dsh-host-apiproxy` 两包删除；`connection.api.settings`
  RPC 面移除，配置读写走 `ctx.remote.settings`（describe 无参直返 / update、replace、
  mutate 位置参数 / 错误 throw）；浏览器令牌 + cookie 认证（覆盖 /api、RPC、WS、
  index 页，不管静态资产与插件自有路由）。

## 本仓能力退役记录

自有插件/能力被官方机制覆盖后退役（按退役时间倒序）：

- `@dsh-plus/web-terminal`：0.2.0-rc.1 适配时下线停维护（官方交互式终端进侧栏，
  分屏为其仅存差异，官方侧栏不支持）。
- `@dsh-plus/web-files` 的会话内「打开文件」手势接管：2026 年移除（官方侧栏文件
  能力覆盖 GUI 内查看诉求，交还宿主 openWorkspacePath）。
- `packages/feature-toggle`：0.1.2-alpha 线退役（官方组合树覆盖其能力，机制要点
  保留在 [插件开发指南](../plugin-dev/插件开发指南.md)）。

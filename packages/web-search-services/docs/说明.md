# web-search-services：web_search 免费后端聚合

> **特例声明（重要）**：本插件是本仓库**唯一的 Python 桥接案例**。dsh-plus
> 集成外部 HTTP 服务的默认做法是 **TS 原生**（进程内 fetch、编译期契约）。
> 本例因需求明确要求复用 search-services skill 已维护的编排逻辑（链内
> fallback、Tavily 多 key 轮转、intent 服务链），才整体桥接其脚本。
> 判定标准与同步策略见 `scripts/README.md`，决策记录见
> [ADR 0003](../../../repo/adr/0003-搜索provider默认TS原生-Python桥接为例外.md)。

经官方 `ctx.web` provider 扩展点，把内置 `web_search` 工具的搜索流量桥接到
search-services skill 的 **Tavily / Exa / OpenAI Chat** 免费额度后端
（skill 脚本的维护副本随本包分发，见 `scripts/`），替代按次计费的
`deepseek-official` 原生搜索。

## 核心契约

- **对官方包零修改**：不注册工具、不改渲染。provider 只产出官方标准
  `WebSearchResult`，`web_search` 的参数、提示词、输出格式（`Sources:` +
  `- [title](url)` + 引用指令）与官方 provider 逐字节一致。
- **provider id**：`search-services`。官方 `dsh-web` 的选择策略只支持
  「pin 单一 id」或「唯一可用自动选中」，无原生优先级链——因此注册一个
  聚合 provider，**优先级与自动回退在 provider 内部、由 skill 的 search.py
  编排**（含 Tavily 多 key 轮转 `TAVILY_API_KEYS`）。
- **web_fetch 不动**：仍走官方免费的 `http` fetch provider。

## 执行链路

```text
web_search 工具（官方 dsh-tool-web，零修改）
  → ctx.web.search()（官方 dsh-web，按 searchProvider pin 选中）
  → SearchServicesProvider（本插件）
  → python3 search.py search --query <q> --service <priority> --max-results <n>
  → skill 链内 fallback（tavily → exa → openai-chat，随 priority 变）
  → 按 selectedService 归一化为 WebSearchResult
```

各后端输出归一化：tavily `results[]`（snippet=content，publishedAt=published_date，
answer→content）；exa `results[]`（url 缺省回退 id，snippet=highlights 拼接）；
openai-chat 生成式回答（content=answer，markdown 链接提取为 sources）。

## 配置

单一 schemastery schema 同时充当 cordis 行级 Config 与 settings 命名空间
`dsh-plus-web-search-services`（用户层落 `$DSH_HOME/settings.yaml`，热生效；
settings 缺席回落行级 config）。

| 字段 | 默认 | 说明 |
|---|---|---|
| `scriptPath` | `''`（随包内置副本） | search.py 路径；空串 = 本包 `scripts/search.py`，非空支持 `~` 展开（可指回 skill 本体） |
| `envFile` | `~/.config/search-services/env` | skill 密钥 env 文件；空串禁用 |
| `python` | `python3` | 解释器 |
| `priority` | `["tavily","exa","openai-chat"]` | 后端优先级，前者失败自动回退后者 |
| `timeoutMs` | `55000` | 子进程超时；应低于 dsh-tool-web 的 `searchTimeoutMs` |
| `keys.*` | 空 | 行级密钥覆盖逃生舱（见下） |

**密钥单事实源**：默认直接读 skill 的 env 文件（本机已有配置零搬迁），
合并顺序为 `进程 env ⊕ envFile ⊕ 行级 keys`（后者优先）。`keys` 的
tavily/exa/openaiApiKey 标了 `role('secret')`，按存储规范**只允许行级
Config 注入**；settings 用户层勿填密钥。

**Context7 不进搜索链**：它只做带库名的 docs 查询，而 `web_search` 的契约
没有 library 概念——传了也会被 skill 跳过。

## 错误面（全部结构化 WebError，模型可读可恢复）

| 场景 | code | 语义 |
|---|---|---|
| 全部后端失败 | `WEB_PROVIDER_ERROR` | 消息含各后端失败摘要（attempts） |
| 调用方取消 | `WEB_ABORTED` | signal 触发，子进程被杀 |
| pin 了本 provider 但不可用 | `WEB_PROVIDER_CONFIGURED_UNAVAILABLE` | 脚本缺失或全后端无 key；**绝不静默回落付费 deepseek** |

`available()` 是廉价本地检查：脚本存在 + 优先级内至少一个后端有 key，无网络调用。

## 生产接线（本机）

bundle-main 已 insert 插件行（随仓库分发）。机器层在 profile patch
（`~/.dsh/profiles/web/cordis.patch.yml`，热应用）：

```yaml
- id: web
  config:
    searchProvider: search-services   # 整行替换，须重述 fetchProvider
    fetchProvider: http
- id: web-search-deepseek
  disabled: true                      # 双保险：pin 失效也不落付费
```

注意：bundle 层新行的生效需要 profile 重载（`/reload`）；在重载前
`web_search` 会返回 `CONFIGURED_MISSING` 结构化错误，重载后即恢复。

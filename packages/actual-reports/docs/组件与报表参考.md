# 组件与报表参考

## 本文定位与权威来源

定制组件要用的字段名、实验开关、报表取值，都能用 `reference` 族从本机现场取到：

- `reference widgets` —— 组件类型与每个类型 meta 的确切字段（读本机官方 CLI 自带的
  `@actual-app/core` 模型源码）；
- `reference prefs` —— 预算里的实验开关与其他偏好（`flags.*` 来自预算 `preferences` 表）；
- `reference source` —— 本机官方源码（`--kind core`）与服务端托管的客户端源码
  （`--kind client`），支持 `--list` / `--grep` / `--file`；
- `reference report-options` —— 报表定义的合法取值。

**工具是权威，本文只是导航与配方**：字段清单随版本变，写之前用工具复核。下文结论来自
服务端 26.10.0 的 `@actual-app/core` 源码与它托管的客户端源码（本机实测读出）。

## 组件的通用形状

- 组件行字段：`id`、`dashboard_page_id`、`type`、`x`、`y`、`width`、`height`、`meta`、`tombstone`；
  页面是 12 列网格。
- 界面新增组件时的默认：`width = 4`、`height = 2`（`sankey-card` 为 `3`）、`meta = null`；
  省略 `x`/`y` 时由服务端自动排版（本包 `dashboard add-widget` 同此行为）。
- 多数图形卡共享这些 meta 字段：`name?`、`conditions?`（官方规则条件数组）、
  `conditionsOp?`（`and` | `or`）、`timeFrame?`。
- `timeFrame` = `{ start, end, mode }`，`mode` 取值：`sliding-window` | `static` | `full` |
  `lastMonth` | `lastYear` | `yearToDate` | `priorYearToDate` | `currentQuarter` |
  `previousQuarter`。静态单日/单月用 `mode: "static"` 加具体起止日期。
- `conditions` 与界面筛选同一套语义（官方 `make-filters-from-conditions`）。

## 各类型的差异字段

只列各类型特有的字段；公共字段见上。`?` 表示可选，写组件时不必给全。

- `net-worth-card`：`interval?`(Daily/Weekly/Monthly/Yearly)、`mode?`(trend | stacked)
- `cash-flow-card`：`showBalance?`
- `spending-card`：`compare?`、`compareTo?`、`isLive?`、`mode?`(single-month | budget | average)、
  `averageRange?`(`{mode:'last-n-months',months:3|6|12}` | `{mode:'year-to-date'}` | `{mode:'all-time'}`)
- `budget-analysis-card`：`interval?`、`graphType?`(Line | Bar)、`showBalance?`、`balanceOnly?`、`showHiddenCategories?`
- `crossover-card`：`expenseCategoryIds?`、`incomeAccountIds?`、`safeWithdrawalRate?`、`estimatedReturn?`、
  `expectedContribution?`、`projectionType?`(hampel | median | mean)、`showHiddenCategories?`、`expenseAdjustmentFactor?`
- `markdown-card`：`content`（必填）、`text_align?`(left | right | center)
- `summary-card`：`content?` —— **JSON 字符串**（不是对象）：
  `{"type":"sum"|"avgPerMonth"|"avgPerYear"|"avgPerTransact"}`，或
  `{"type":"percentage","divisorConditions":[…],"divisorConditionsOp":"and"|"or","divisorAllTimeDateRange"?}`
- `calendar-card`：无差异字段（靠 `timeFrame` 与 `conditions` 定位）
- `formula-card`：`formula?`、`fontSize?`、`fontSizeMode?`(dynamic | static)、`staticFontSize?`、
  `showTitle?`、`colorFormula?`、`queriesVersion?`、`queries?`（`{ <名字>: { conditions?, conditionsOp?, timeFrame? } }`）
- `custom-report`：`{ id }` —— **必填**，指向一张已存报表（`report list` 取 id）
- `sankey-card`：`mode?`(budgeted | spent)、`topNcategories?`、`categorySort?`(per-group | global | budget-order)、
  `showPercentages?`、`groupAccounts?`、`showTransfers?`、`layerFrom?`、`layerTo?`
- `balance-forecast-card`：`startDate?`、`endDate?`、`accounts?`、`granularity?`(Daily | Monthly)、`source?`
- `age-of-money-card`：`granularity?`(daily | weekly | monthly)
- `monte-carlo-card`：`pots?`、`withdrawalStrategy?`、`returnModel?`、`withdrawalRule?`、`minimumSpending?`、
  `spendingPhases?`、`contributions?`、`incomeStreams?`、`inflationMean?`、`inflationStdDev?`、`taxModel?`、
  `taxBands?`、`currentAge?`、`targetAge?`、`simulationCount?`

准确清单（含字段类型与嵌套结构）用 `reference widgets --type <类型>` 取。

## 实验开关门控

受开关门控的类型（开关名来自客户端 `useFeatureFlag(...)` 的调用点，存放在预算
preferences 的 `flags.<名>`）：

| 组件类型 | 开关 |
| --- | --- |
| `formula-card` | `formulaMode` |
| `sankey-card` | `sankeyReport` |
| `budget-analysis-card` | `budgetAnalysisReport` |
| `balance-forecast-card` | `balanceForecastReport` |
| `monte-carlo-card` | `monteCarloReport` |

开关没开时**写入会成功，界面却不渲染**这张卡片 —— 先 `reference prefs` 查，没开就请用户
在界面的实验功能里打开，别硬写。其余开关（`newSidebarUI`、`customThemes`、`enableBanking` 等）
不门控仪表盘组件。

## 报表字段取值

`reference report-options` 给出全部合法取值：实时区间 12 个（`This week` … `All time`）、
粒度 4 个、分组 6 个（Category / Group / CategoryGroup / Payee / Account / Interval）、
口径 6 个（Payment / Deposit / Net / Net Payment / Net Deposit / Budgeted）、排序 4 个
（asc / desc / name / budget）、模式 2 个（total / time）。静态区间用
`isDateStatic: true` + `startDate`/`endDate`（`yyyy-MM-dd`）。

本包**未实现**的分组/口径（`groupBy=Tag`、`balanceType=Budgeted`）会显式报错，不会静默
算错；要预算口径的数字，走公式卡的预算查询（见下）。

## 常见定制配方

写入与读回可以验证，**渲染效果只能在界面确认** —— 交付后请用户刷新界面看一眼。

1. **今日支出**（不需要实验开关）：`summary-card` + 静态单日 `timeFrame` + `content` 求和。
   meta 形如
   `{"name":"今日支出","timeFrame":{"start":"<今天>","end":"<今天>","mode":"static"},"content":"{\"type\":\"sum\"}"}`。
   注意 `content` 是 JSON 字符串；要剔除收入就用 `conditions` 加分类组条件。
2. **本月日均支出**：`summary-card` 的 content 只有 `sum`/`avgPerMonth`/`avgPerYear`/`avgPerTransact`，
   **没有按天平均**。要「本月合计 ÷ 已过天数」得用 `formula-card`（`formula` 里用
   `QUERY` / `BUDGET_QUERY` 取数、用日期函数算天数）；接受「平均每月」口径就直接用
   `avgPerMonth`。公式族可用函数名可在本机客户端源码里查：
   `reference source --kind client --grep BUDGET_QUERY --context 2`。
3. **本月支出排名**：先建报表（`groupBy=Category`、`interval=Monthly`、`balanceType=Payment`、
   合适的 `graphType`），再用 `custom-report` 组件引用它（meta 只写报表 id）。
4. **剩余日均预算（剔除收入）**：需要同时读预算与剩余天数，落在 `formula-card`
   （`BUDGET_QUERY` + 剩余天数）；写之前先 `reference prefs` 看 `formulaMode` 是否开启。
5. **常规图形卡**（净值、现金流、支出）：现场多半已有同类组件，直接
   `dashboard widgets --page-id <页>` 读一个照抄 meta 最省事。

## 源码检索示例

```bash
actual-reports reference widgets --type formula-card
actual-reports reference prefs
actual-reports reference source --kind client --grep "dateRangeOptions" --context 2
actual-reports reference source --kind client --file src/components/reports/ReportOptions.ts
actual-reports reference source --kind core --list --match reports/
```
